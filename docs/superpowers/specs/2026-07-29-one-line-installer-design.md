# 一键安装脚本设计

## 1. 背景与目标

项目目前需要手动创建虚拟环境、安装 Python 包、安装前端依赖、构建前端，并自行创建全局 CLI 链接。新增根目录 `install.sh`，把这些步骤收敛为一条命令，同时支持以下两种入口：

- 未下载仓库时，通过 GitHub 上的脚本远程安装或更新。
- 已下载仓库时，在仓库根目录直接安装当前代码。

两种入口都应创建可在任意终端目录使用的 `codex-task-monitor` 命令，不要求激活虚拟环境。

## 2. 用户命令

远程一行安装：

```bash
curl -fsSL https://raw.githubusercontent.com/DhWU-coder/codex-task-monitor/main/install.sh | bash
```

已下载仓库后，在仓库根目录安装：

```bash
bash install.sh
```

## 3. 安装模式

脚本自动判断安装模式：

- 脚本所在目录同时包含 `pyproject.toml` 和 `frontend/package.json` 时，使用该目录作为本地源码目录。
- 通过标准输入执行且没有可用本地仓库时，使用远程模式，将仓库安装到 `${HOME}/.local/share/codex-task-monitor`。
- `--remote` 可显式选择远程模式，主要用于自动化验证和故障排查。

远程安装目录可通过 `CODEX_TASK_MONITOR_INSTALL_DIR` 覆盖，全局命令目录可通过 `CODEX_TASK_MONITOR_BIN_DIR` 覆盖，Python 命令可通过 `CODEX_TASK_MONITOR_PYTHON` 覆盖。

## 4. 安装流程

本地模式直接使用当前仓库；远程模式在默认安装目录不存在时克隆公开仓库，存在且属于正确 Git 仓库时执行仅快进更新。随后统一执行：

1. 校验 Git（仅远程模式）、Python 3.12 及以上版本和 npm。
2. 在源码目录创建或复用 `.venv`。
3. 以可编辑方式安装项目。
4. 使用 `npm ci` 安装锁定的前端依赖并执行生产构建。
5. 在 `${HOME}/.local/bin/codex-task-monitor` 创建指向虚拟环境 CLI 的符号链接。
6. 执行 `codex-task-monitor --help` 验证入口并打印后续命令。

配置文件继续位于实际源码目录的 `config.yaml`，默认 UI 端口仍为 `6664`。

## 5. 安全与错误处理

- 使用 Bash 严格模式，任一步失败即停止并返回非零状态。
- 远程安装目录已经存在但不是预期仓库时拒绝继续，不删除或覆盖目录。
- 更新已有远程安装时只允许快进合并；本地改动或分叉导致无法快进时停止并提示用户处理。
- 全局命令路径已是普通文件或目录时拒绝覆盖；已是符号链接时允许原子更新指向。
- 如果全局命令目录不在 `PATH`，安装仍完成，但明确打印需要加入 Shell 配置的命令。
- 日志不得打印配置中的飞书凭据。
- 提供 `--dry-run`，只展示模式、路径和将执行的动作，不修改文件系统。

## 6. 测试与验收

自动化测试直接运行真实 Bash 脚本的 `--dry-run`：

- 验证本地仓库被正确识别，且输出源码目录和全局命令路径。
- 验证显式远程模式使用公开仓库地址及可覆盖的安装目录。
- 验证全局命令路径为普通文件时脚本拒绝覆盖。
- 验证前端命令始终在目标仓库的 `frontend` 目录内执行，避免 npm 把外部当前目录误识别为项目根目录。
- 使用 `bash -n install.sh` 校验 Shell 语法。

最终还需运行项目完整的后端、前端、静态检查和生产依赖审计，确保安装器与文档变更没有破坏现有功能。

## 7. 非目标

- 不安装 Python、Node.js、npm 或 Git 等系统依赖。
- 不修改用户的 `~/.zshrc`、`~/.bashrc` 或其他 Shell 配置。
- 不注册系统服务或登录启动项。
- 不提供 Homebrew、PyPI 或容器分发。
- 不自动启动监控器，也不修改用户已有的 `config.yaml` 内容。
