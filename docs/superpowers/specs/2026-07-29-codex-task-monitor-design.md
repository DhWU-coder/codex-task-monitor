# Codex 任务监控器设计

## 1. 背景

本项目在 `/Users/wudonghao/python_program/codex-task-monitor` 中从零实现一个本机 Codex 任务监控器。用户通过本地 Web UI 查看正在运行的 Codex 任务，为任务启用监控，并在任务完成、失败、中断、等待输入或等待审批时，由飞书自建应用机器人向预先配置的用户发送私聊通知。

当前目录不是 Git 仓库，仅包含 `.idea` 和 Python 3.14 虚拟环境。首版不创建分支、不执行 Git 写操作，也不操作或改变被监控的 Codex 任务。

## 2. 已确认目标

- 仅监控本机可发现的 Codex 桌面应用和 CLI 任务。
- 提供本地 Web UI，首版仅监听 `127.0.0.1`。
- 主界面使用任务卡片，默认显示运行中任务。
- 支持“运行中”“需处理”“最近完成”“全部”四种筛选。
- 支持“仅监控当前轮”和“持续监控任务”两种模式。
- 对正常完成、失败、中断、等待用户输入和等待审批发送飞书通知。
- 监控器重启后只恢复仍在运行的任务；已经结束的任务不补发通知。
- 飞书通知包含任务标题、项目名、项目目录、Git 分支（如有）、状态、运行时长、事件时间和最新回复摘要。
- 飞书凭据和其他设置保存在 `config.yaml`，并可通过 UI 修改。
- 提供 `codex-task-monitor start|run|stop|restart` 命令。
- `run` 前台运行；`start` 后台运行；`stop` 优雅停止；`restart` 重启。
- `run`、`start` 和 `restart` 成功后打印 UI 地址。
- UI 端口由 `config.yaml` 配置，默认值为 `6664`。

## 3. 明确不在首版范围内

- 从监控器启动、打断、归档、删除或修改 Codex 任务。
- 局域网或公网访问、账号登录和远程认证。
- 多个飞书接收人。
- 完整 Codex 对话、完整命令输出或完整思维过程展示。
- macOS 登录后自动启动。
- 操作飞书桌面客户端。
- 依赖 Codex 桌面宿主注入的私有 `codex_app.*` 工具。

## 4. 技术边界与方案选择

官方 Codex App Server 提供 `thread/list`、`thread/read`、`thread/status/changed`、`turn/completed`、审批请求和用户输入请求等能力，也支持通过 stdio 使用 JSONL 承载双向 JSON-RPC。参考：

- [Codex App Server](https://learn.chatgpt.com/docs/app-server.md)
- [Codex App Server 源码](https://github.com/openai/codex/tree/main/codex-rs/app-server)

本机实测存在多个彼此独立的 `codex app-server` 进程。官方文档没有承诺一个新启动的 App Server 会聚合其他进程的全部运行时状态。因此采用已经确认的混合只读方案：

1. 官方 App Server 是任务清单、线程详情和当前连接事件的首选来源。
2. 本地会话观察器只读跟踪 Codex 持久化会话的增量变化，用于补足其他桌面或 CLI 进程。
3. 状态聚合器将两个来源归一化，并按可靠性规则解决冲突。
4. 所有内部会话格式解析封装在独立适配层中；解析失败时降级为“数据异常”，不误报终态。

## 5. 总体架构

### 5.1 后端

使用 Python、FastAPI 和异步任务：

- `codex_adapter`：管理 App Server 子进程、JSON-RPC 请求和事件。
- `session_observer`：只读发现、增量跟踪和解析本地 Codex 会话。
- `monitoring`：任务模型、状态归一化、监控规则和事件去重。
- `notifications`：飞书鉴权、消息格式化、重试和结果记录。
- `storage`：SQLite 持久化和 `config.yaml` 原子读写。
- `web`：REST API、SSE、静态资源和健康检查。
- `cli`：`start`、`run`、`stop`、`restart` 生命周期管理。

各模块通过显式数据模型和接口通信，禁止 UI、飞书客户端或本地会话解析器直接互相调用。

### 5.2 前端

使用 Vue 3、TypeScript 和 Vite：

- REST API 用于初始化、筛选、监控操作和配置保存。
- SSE 用于任务状态、连接状态和通知结果的实时更新。
- 构建产物由 FastAPI 提供，运行时只启动一个服务。

### 5.3 持久化

SQLite 只保存：

- 监控任务和监控模式；
- 启用监控时的线程、Turn 和基线状态；
- 通知幂等键；
- 通知发送结果；
- 必需的任务显示快照。

SQLite 不保存完整对话、完整工具输出或飞书访问令牌。`tenant_access_token` 只保存在进程内存中。

## 6. 领域模型

### 6.1 任务状态

- `running`：Turn 正在执行。
- `waiting_approval`：等待命令、文件修改或权限审批。
- `waiting_input`：等待用户回答。
- `completed`：Turn 正常结束。
- `failed`：Turn 失败或线程发生系统错误。
- `interrupted`：Turn 被取消。
- `unknown`：暂时无法获得可靠状态。
- `source_error`：来源存在明确解析或连接异常。

状态优先级为：

1. 带 Turn ID 的 App Server 终态事件；
2. App Server 审批或输入请求；
3. App Server 线程快照和 `thread/read`；
4. 本地会话中的持久化 Turn 或 Item 事件；
5. 文件更新时间只更新“最近活动”，不能单独产生终态。

连接断开、文件暂时不可读或数据源冲突都不得被解释为任务完成。

### 6.2 任务身份

- 任务主键使用 `thread_id`。
- 当前执行轮次使用 `turn_id`。
- 标题优先使用线程 `name`，缺失时使用 `preview`，再次缺失时使用线程 ID 的短形式。
- 工作目录优先使用线程元数据，再使用本地会话元数据。
- 项目名优先使用 Git 根目录名；不是 Git 仓库时使用工作目录名。
- 分支优先使用线程 `gitInfo.branch`；缺失时以参数数组调用只读 Git 命令并设置超时。

所有 Git 查询都使用结构化参数，不拼接 Shell 字符串。

## 7. 监控规则

### 7.1 仅监控当前轮

- 只能对当前处于 `running`、`waiting_approval` 或 `waiting_input` 的任务启用。
- 启用时绑定 `thread_id + turn_id` 并记录基线状态。
- 基线本身不触发通知；启用之后出现的新状态才触发。
- 等待审批和等待输入分别发送一次通知，但继续监控。
- 当前 Turn 完成、失败或中断后发送一次终态通知并自动停用监控。

### 7.2 持续监控

- 启用时绑定 `thread_id`，当前运行中的 Turn 立即纳入监控。
- 当前 Turn 结束后继续保留监控。
- 同一线程之后开始的新 Turn 自动纳入。
- 每个 Turn 独立处理等待事件和终态。
- 用户手动停止后不再发送新通知。

### 7.3 重启恢复

- 启动时读取持久化监控记录并重新获取任务状态。
- 只有任务仍处于运行或等待状态时才恢复。
- 任务在停机期间已经结束时，停用该监控记录，不补发通知。
- 历史发送失败的通知不会在重启后自动重发。

### 7.4 幂等

- 终态键：`thread_id + turn_id + terminal_status`。
- 等待键：优先使用 `thread_id + turn_id + request_id`，没有请求 ID 时使用 Item ID。
- 只有飞书确认成功后记录 `sent`。
- 同一次运行中的临时网络错误可有限重试。
- SQLite 无法可靠写入幂等记录时暂停自动发送，避免重复轰炸。

## 8. 数据采集

### 8.1 App Server

- 使用 `codex app-server --listen stdio://` 启动独立子进程。
- 每次连接只执行一次 `initialize`，随后发送 `initialized`。
- `thread/list` 显式包含稳定的顶层来源，首版排除 sub-agent 来源，并使用 `useStateDbOnly: true` 避免列表读取触发日志扫描修复。
- `thread/read` 用于补全选中任务和监控任务的最新 Turn。
- 使用 `thread/status/changed`、`turn/started`、`turn/completed`、审批请求和输入请求更新状态。
- 进程异常退出后按 1、2、4、8 秒递增重连，最高间隔 30 秒。
- 重连成功后立即执行一次全量对账。

本机 Codex CLI 当前核验版本为 `0.146.0`。实现时生成与本机版本匹配的 JSON Schema，并只依赖首版需要的字段。

### 8.2 本地会话观察

- Codex 数据根目录优先读取 `CODEX_HOME`，未设置时使用当前用户的默认 Codex 数据目录。
- 只读发现活动会话文件，按文件标识和字节偏移增量读取。
- 支持追加写、半行 JSON、文件替换、轮转和重复事件。
- 只提取线程、Turn、状态、标题、工作目录、Git 信息、时间戳和必要的最新摘要。
- 未识别的记录类型安全忽略；关键记录解析失败时上报来源错误。
- 不打开写模式，不修复、不迁移、不删除 Codex 文件。

### 8.3 对账

- App Server 事件即时应用。
- 默认每 2 秒刷新活动任务快照。
- 默认每 30 秒执行完整对账。
- 终态首次出现时先短暂确认；来源冲突时等待下一次快照。
- 终态确认后更新 UI，并仅对已启用监控的任务进入通知流程。

## 9. 飞书通知

使用飞书自建应用机器人，以应用身份获取 `tenant_access_token`，并调用发送消息接口向配置用户私聊。参考：

- [飞书发送消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/create?lang=zh-CN)
- [飞书 API 调用流程](https://open.feishu.cn/document/server-docs/api-call-guide/calling-process/get-?lang=zh-CN)

默认使用 `receive_id_type: open_id`，同时允许在配置中选择飞书接口支持的其他用户 ID 类型。

### 9.1 消息内容

终态消息包含：

- 任务标题；
- 项目名；
- 项目目录；
- Git 分支（如有）；
- 完成、失败或中断状态；
- 运行时长；
- 事件时间；
- 最新回复的截断摘要；
- 失败时的安全错误摘要。

等待消息包含同样的任务定位信息，以及等待审批或等待输入的安全摘要。

### 9.2 安全与重试

- `app_secret`、访问令牌和用户标识不得写入日志。
- 访问令牌按过期时间缓存并提前刷新。
- 鉴权失效时强制刷新一次。
- 网络错误、限流和服务端错误最多重试三次，使用指数退避和抖动。
- 凭据错误、权限不足和目标用户不可用等配置错误不循环重试。
- 发送失败在 UI 展示，用户可以显式手动重试。
- 自动化测试使用模拟 HTTP，不发送真实飞书消息。
- 只有用户主动点击“测试飞书通知”才发送测试消息。

## 10. 配置

项目根目录包含 `config.yaml`，默认配置：

```yaml
server:
  host: 127.0.0.1
  port: 6664

codex:
  command: codex
  refresh_interval_seconds: 2
  reconcile_interval_seconds: 30
  recent_completed_hours: 24

feishu:
  app_id: ""
  app_secret: ""
  receive_id: ""
  receive_id_type: open_id

notifications:
  enabled: true
  summary_max_length: 500
  notify_completed: true
  notify_failed: true
  notify_interrupted: true
  notify_waiting_input: true
  notify_waiting_approval: true
```

配置规则：

- `server.host` 首版只允许回环地址。
- `server.port` 默认 `6664`，由 UI 和 CLI 共同读取。
- UI 查询配置时不返回完整 `app_secret`。
- `app_secret` 留空表示保留原值，显式清除才删除。
- 保存时先验证完整配置，再使用临时文件和原子替换。
- macOS 上将配置文件权限设置为 `0600`，数据目录设置为 `0700`，SQLite 和运行状态文件设置为 `0600`。
- 飞书和通知配置保存后立即生效。
- 地址和端口保存后提示重启生效。
- 配置无效时不覆盖原文件；服务保留最后一份有效内存配置并展示错误。

## 11. CLI 生命周期

通过 `pyproject.toml` 注册控制台入口 `codex-task-monitor`。

### 11.1 `run`

- 在前台运行服务。
- 启动完成后打印 `UI 地址：http://127.0.0.1:6664`，实际端口来自配置。
- 接收 `SIGINT` 和 `SIGTERM` 后优雅关闭 App Server、观察器、数据库和 SSE 连接。

### 11.2 `start`

- 检查运行状态、PID 文件和端口占用。
- 已运行时不重复启动，打印现有 UI 地址。
- 后台启动服务，将 PID、启动时间和配置路径写入运行状态文件。
- 日志写入本地运行日志文件。
- 等待健康检查成功后再返回，并打印 UI 地址。
- 启动超时或子进程提前退出时返回非零退出码并展示日志位置。

### 11.3 `stop`

- 校验 PID 对应的是本项目服务，处理陈旧 PID 文件。
- 发送 `SIGTERM` 并等待优雅退出。
- 超时后只终止已经确认属于本监控器的目标进程。
- 清理运行状态文件。

### 11.4 `restart`

- 按 `stop` 语义停止，再按 `start` 语义启动。
- 启动完成后打印新的 UI 地址。

CLI 默认读取项目根目录的 `config.yaml`，配置路径不随调用命令时的当前工作目录变化。解析顺序为：

1. 如果设置了 `CODEX_TASK_MONITOR_CONFIG`，使用该绝对路径。
2. 否则从已安装的本项目 Python 包定位源码项目根目录，并读取其中的 `config.yaml`。

SQLite、PID、运行状态和日志默认位于有效配置文件同级的 `data` 目录。首版命令从本项目的已安装入口运行，不支持管理远程实例。

## 12. Web UI

### 12.1 主页面

顶部状态栏显示：

- Codex App Server 状态；
- 本地会话观察状态；
- 飞书配置状态；
- 最近同步时间；
- 正在监控的任务数量。

筛选：

- `运行中`：默认；
- `需处理`：等待输入或审批；
- `最近完成`：默认最近 24 小时；
- `全部`。

任务卡片显示：

- 标题和状态徽标；
- 项目名、目录和分支；
- 任务来源；
- 运行时长和最近活动时间；
- 当前监控模式；
- `监控当前轮`、`持续监控`、`停止监控` 和 `查看详情` 操作。

详情仅展示任务标识、最新摘要、当前待处理内容、最近状态变化和最近通知结果，不默认展示完整对话。

### 12.2 设置页

- 编辑 `config.yaml` 中允许修改的字段。
- 密钥默认遮罩。
- 提供配置校验和保存结果。
- 提供“测试飞书通知”按钮。
- 明确提示端口修改需要执行 `codex-task-monitor restart`。

### 12.3 API

首版 REST API 至少覆盖：

- 获取任务列表与详情；
- 启用当前轮监控；
- 启用持续监控；
- 停止监控；
- 获取经过遮罩的配置；
- 校验和保存配置；
- 发送测试通知；
- 获取健康状态。

SSE 只推送安全投影后的任务、连接状态和通知结果。

### 12.4 本地 Web 安全

- 服务只接受回环地址上的请求。
- 不启用跨域访问。
- 校验 `Host`，只允许当前配置的回环主机和端口。
- 所有修改配置、监控状态或发送测试消息的接口只接受 JSON。
- 修改类请求必须携带由服务生成的 CSRF 令牌，并校验同源 `Origin` 或 `Referer`。
- 配置响应永远不包含完整 `app_secret`。
- SSE 和日志只包含安全投影，不推送凭据、完整对话或完整命令。

## 13. 错误处理

- App Server 断开：展示断线状态、自动重连，本地观察继续工作。
- 本地格式变化：隔离到适配器，任务标记来源异常，不误判终态。
- 数据源冲突：延迟终态确认并对账。
- 飞书失败：有限重试、持久化失败原因、允许手动重试。
- 配置失败：拒绝保存，不覆盖有效配置。
- SQLite 失败：暂停自动通知，保留 UI 错误信息。
- SSE 断开：浏览器自动重连并重新获取完整快照。
- 端口占用：CLI 返回非零状态并提示配置位置。
- 陈旧 PID：验证后清理，不终止无关进程。

## 15. 验收标准

1. 安装本项目后可从任意终端工作目录执行 `codex-task-monitor run|start|stop|restart`，并读取同一份有效配置。
2. `run`、`start` 和 `restart` 成功后打印从配置读取的 UI 地址。
